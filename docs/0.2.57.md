# Silique 0.2.57

## English

- Setting a device as the source of truth now finishes with a real upload: the reset drains the
  outgoing queue until it is actually empty, pulls once more, and verifies both invariants — zero
  diverged notes and zero pending revisions. When either one fails, the result says the reset is
  incomplete instead of reporting success, and it shows how many revisions are still waiting.
- Other devices now learn about it. The reset writes a small internal marker into the vault's own
  encrypted history (invisible: it is not a note, it never shows in the list, search, vault export or
  the Android widgets). Any device that pulls a newer marker holds that vault: revisions are stored
  and the read position advances, but nothing is applied — no note, folder or metadata changes, and
  nothing is uploaded while it waits.
- The waiting vault says so in the app itself, not only in a dialog: a banner above the notes names
  the device and states that the new server version has not been downloaded. Opening it offers
  exactly three decisions — "Zapisz kopię i pobierz" (a full vault export first, then the download),
  "Pobierz wersję z serwera", or "Później". Nothing is adopted without that decision, "later" keeps
  the vault held, and the hold survives a restart. Adoption replaces only the local versions the
  server actually superseded; notes that exist only on this device and hidden notes keep syncing
  normally, and a second adoption changes nothing.
- Every long action now shows progress on the button that is pressed (a small spinner inside that one
  button, the other actions disabled until it settles), so a slow reset or download no longer looks
  like a dead click.
- Android: a long operation continues when the app is backgrounded. A local operation journal records
  the running operation before it starts and settles it afterwards; if the system kills the process,
  the next launch resumes an interrupted full pull, flush or reset automatically once the vault is
  unlocked (adoption is never resumed automatically, because it always needs your decision). While
  the operation runs, a foreground notification keeps the process alive.
- No protocol, crypto, DAG or data-migration changes and no server change: the server is still a dumb
  immutable store, and the new marker travels as ordinary encrypted vault history.
- Android: same signing key, installing over the previous version works normally.
- macOS: manual installation from the DMG is still required (self-signed build).
- Evidence: `flutter analyze` clean, full suite green (1238 passed, 46 skipped), 20 new tests covering
  the incomplete-drain report, per-action spinners, the marker round-trip and its invisibility in the
  note list, export plan, search and widget snapshot, the hold changing no document/folder/metadata
  row, the hold across a restart, an unaffected second vault, adoption requiring the decision, the
  preserved local-only and hidden revisions, and the operation journal across a restart with its
  resume rules. Two independent review rounds returned blocking findings that were fixed and
  re-reviewed; the final reviews returned no blocking findings. The native Android service is
  verified by the release APK build. Design and non-goals: `docs/sync-recovery.md`.

## Polski

- Ustawienie urządzenia jako źródła prawdy kończy się teraz faktycznym wysłaniem: reset opróżnia kolejkę
  wychodzącą do zera, pobiera jeszcze raz i weryfikuje oba warunki — zero notatek rozbieżnych i zero
  oczekujących rewizji. Jeśli którykolwiek nie jest spełniony, wynik mówi, że reset jest nieukończony,
  zamiast ogłaszać sukces, i pokazuje, ile rewizji jeszcze czeka.
- Inne urządzenia dowiadują się o tym. Reset zapisuje mały wewnętrzny znacznik w zaszyfrowanej
  historii samego vaulta (niewidoczny: nie jest notatką, nie pojawia się na liście, w wyszukiwaniu,
  w eksporcie vaulta ani w widżetach Androida). Urządzenie, które pobierze nowszy znacznik, wstrzymuje
  ten vault: rewizje są zapisywane, pozycja odczytu przesuwa się, ale nic nie jest stosowane — żadna
  notatka, folder ani metadana się nie zmienia, a wstrzymany vault nic nie wysyła.
- Wstrzymany vault mówi o tym w samej aplikacji, nie tylko w dialogu: baner nad notatkami podaje
  nazwę urządzenia i informuje, że nowa wersja z serwera nie została pobrana. Otwarcie go daje trzy
  decyzje — „Zapisz kopię i pobierz” (najpierw pełny eksport vaulta, potem pobranie), „Pobierz wersję
  z serwera” albo „Później”. Nic nie jest przejmowane bez tej decyzji, „później” zostawia vault
  wstrzymany, a wstrzymanie przeżywa restart. Przejęcie zastępuje tylko te lokalne wersje, które
  serwer faktycznie zastąpił; notatki istniejące wyłącznie na tym urządzeniu oraz notatki ukryte
  synchronizują się dalej normalnie, a drugie przejęcie nic nie zmienia.
- Każda długa akcja pokazuje teraz postęp na wciśniętym przycisku (małe kółko w tym jednym przycisku,
  pozostałe nieaktywne do zakończenia), więc wolny reset czy pobieranie nie wyglądają już jak martwy
  klik.
- Android: długa operacja trwa, gdy aplikacja jest w tle. Lokalny dziennik operacji zapisuje działanie
  przed startem i rozlicza je po zakończeniu; jeśli system zabije proces, następne uruchomienie
  wznowi przerwane pełne pobranie, wysyłkę lub reset automatycznie po odblokowaniu vaulta (przejęcie
  nigdy nie jest wznawiane automatycznie, bo zawsze wymaga Twojej decyzji). Na czas operacji
  powiadomienie w pasku statusu trzyma proces przy życiu.
- Brak zmian protokołu, szyfrowania, DAG i migracji danych oraz brak zmian po stronie serwera — serwer
  pozostaje niemym, niezmiennym magazynem, a nowy znacznik jedzie jako zwykła zaszyfrowana historia.
- Android: ten sam klucz podpisu, instalacja nad poprzednią wersją działa normalnie.
- macOS: nadal wymagana ręczna instalacja z DMG (build self-signed).
- Dowody: `flutter analyze` czysto, pełny zestaw zielony (1238 przeszło, 46 pominiętych), 20 nowych
  testów obejmujących raport o nieukończonym resecie, kółka postępu per akcja, round-trip znacznika
  i jego niewidoczność na liście notatek, w planie eksportu, w wyszukiwaniu i w snapshocie widżetów,
  wstrzymanie niezmieniające żadnego dokumentu, folderu ani metadanej, wstrzymanie przeżywające
  restart, brak wpływu na drugi vault, przejęcie wymagające decyzji, zachowanie notatek istniejących
  tylko lokalnie i notatek ukrytych oraz dziennik operacji po restarcie z jego regułami wznawiania.
  Dwa niezależne roundy review zwróciły blokujące uwagi, które naprawiono i sprawdzono ponownie;
  końcowe review nie zgłosiły blokerów. Natywna usługa Androida jest weryfikowana przez build APK
  wydania. Projekt i nie-cele: `docs/sync-recovery.md`.
