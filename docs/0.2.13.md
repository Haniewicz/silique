## Phone editor regression

The phone document now has one document-sized scroll owner in both live and
source modes. The live Markdown field is content-sized; it does not share an
independent expanding viewport with `NestedScrollView`. Its unbounded Stack
passes through constraints rather than expanding a separate overlay.

`test/typing_growth_regression_test.dart` is layout-compatible with both the
released 0.2.12+21 layout and the candidate. It sends actual Android text-input
editing values after coordinate taps, keyboard opening and a mid-note scroll.
It checks the editable, controller, focus and native input-client identities,
exact text/selection, scroll position and caret geometry above the keyboard.

## Local hidden notes

Hidden notes use a random local key wrapped by an additional password-derived
Argon2id key, with authenticated AES-GCM envelopes and note/vault-bound contexts.
The existing application, vault and sync cryptographic identifiers are unchanged.
The password is not recoverable. The key is forgotten on locking; disk contents
are encrypted even while unlocked. UI controllers/lists are cleared on locking.

- First creation/move requests password creation and confirmation.
- Open/edit stays hidden; only an explicit move to ordinary notes decrypts it.
- Hidden creation and edits never create ordinary revisions, Markdown mirrors or
  sync uploads. Photos are embedded inside the hidden envelope; moving out restores
  chunked encrypted photo assets rather than exceeding the text revision limit.
- Default policy: five minutes of inactivity, plus background locking. Settings
  offer 1/5/15 minutes or no idle limit, and a background-lock switch. Leaving the
  hidden section and closing the app also lock it.
- These notes are local to this device, not a second synchronized vault. Moving
  an already-synced note requires the owner connection and an explicit warning:
  ordinary copies/history are purged from the server and other devices on sync.
  An acknowledged purge permanently retires that sync identity; explicit move-out
  creates a fresh ordinary identity for a server-owned vault.
- A durable encrypted recovery copy survives an ambiguous remote response. A lost
  purge acknowledgement is retried idempotently, not converted into data loss.
  Hidden/retired identities cannot reappear through stale normal saves or pulls.
- Local database transitions are transactional. Interrupted ordinary/mirror cleanup
  is completed when the vault next opens. SQLite secure deletion and a truncated
  WAL remove former plaintext from active database files after a successful move.
  Existing exports, external backups, snapshots and forensic flash remnants are
  not retroactively encrypted or guaranteed erased.

## Executed checks so far

- Full local `flutter test --no-pub --reporter json`: 298 passed, 15 skipped,
  no failures. Skips require native environments or a disposable API.
- Separate default-limit disposable HTTP server: sync convergence/integration and
  hidden local-move suites passed; repeated runs must respect the public
  registration cooldown. 75 large-note edits produced about 20 syncs, 116-118
  actual HTTP requests, 37 upload batches, zero errors and an empty outbox.
  Conflict reconciliation produced 28 requests / 4 batches; the final round
  added zero batches.
- Hidden unit tests reproduce and cover stale saves, non-atomic local moves,
  interrupted credential setup, lost remote DELETE acknowledgement, blocked-queue
  expiry, attachment preservation and active SQLite/WAL plaintext cleanup.
- Home-screen flows cover first password, move into Hidden, private editing,
  explicit reveal and first hidden creation. Narrow-phone settings overflow was
  reproduced and fixed with an expanded policy selector.

These results are not substitutes for installer builds, independent review or a
physical-phone smoke test. No production server changes are part of this release.
