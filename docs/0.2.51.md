# Silique 0.2.51

## English

- Fixed: appearance settings could not be changed at all while a vault belonged to an account
  but the app had no owner session (logged out, expired session or a different account). The
  compact-mode switch — and every other appearance preference: folder colour, note colour,
  default note/folder colour and folder order — failed with
  `Bad state: Connect the vault owner's account.` The change is now kept locally as a pending
  edit and is pushed by the next sync after you sign in, instead of being rejected.
- Unchanged where it matters: a vault that is *not* offline-tolerant (renaming a synced vault)
  still refuses the write without the owner session and restores the previous metadata.
- Normal (signed-in) behaviour is untouched: the same requests, the same version compare-and-swap.
- No data-layer or crypto changes: no migration, no re-login, no vault re-unlock needed.
- Android: same signing key, installing over the previous version works normally.
- macOS: manual installation from the DMG is still required (self-signed build).
- Evidence: full client test suite green (1141 tests), new regression test proved red on the
  pre-fix commit (adapter RED gate) and green after the fix; `flutter analyze` clean.

## Polski

- Naprawione: nie dało się zmienić ustawień wyglądu, gdy vault należał do konta, ale aplikacja
  nie miała sesji właściciela (wylogowanie, wygasła sesja albo inne konto). Przełącznik trybu
  kompaktowego — i każda inna preferencja wyglądu: kolor folderu, kolor notatki, domyślne kolory
  notatki/folderu oraz kolejność folderów — kończył się komunikatem
  `Bad state: Połącz konto właściciela vaulta.` Zmiana zostaje teraz lokalnie jako oczekująca
  i wchodzi na serwer przy najbliższej synchronizacji po zalogowaniu, zamiast być odrzucona.
- Bez zmian tam, gdzie to istotne: vault, który *nie* toleruje pracy offline (zmiana nazwy
  zsynchronizowanego vaulta), nadal odmawia zapisu bez sesji właściciela i przywraca poprzednie
  metadane.
- Zwykłe zachowanie (zalogowany właściciel) bez zmian: te same żądania, ten sam warunek wersji.
- Brak zmian w warstwie danych i szyfrowania: żadnej migracji, ponownego logowania ani
  odblokowywania vaulta.
- Android: ten sam klucz podpisu, instalacja nad poprzednią wersją działa normalnie.
- macOS: nadal wymagana ręczna instalacja z DMG (build self-signed).
- Dowody: pełny zestaw testów klienta zielony (1141 testów), nowy test regresyjny był czerwony
  na commicie sprzed poprawki (bramka RED adaptera) i zielony po niej; `flutter analyze` czysty.
