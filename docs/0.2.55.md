# Silique 0.2.55

## English

- Fixed: synchronization could stay blocked forever on a vault whose history cites an image that no
  longer exists locally (for example an image that was removed from a note or purged after it had
  already been sent to a previous server). When the vault was re-uploaded to another server, every
  batch carrying such a reference was rejected with `409 Image not uploaded yet`, so the whole
  history stayed stuck — and no local bytes were left to satisfy the server.
- The upload now lists only image references whose bytes are still available locally, and re-filters
  an already queued batch the same way, using a fresh batch identifier. The note content and the
  revision payloads are never modified: only the server-side image reference list is reduced. The
  affected historical version may show a placeholder for that one image on another device; the notes
  and all other history are unaffected.
- An image the server reports as purged is no longer treated as uploaded, so it cannot keep a batch
  failing silently; the retry then proceeds with the remaining references.
- No protocol, crypto, DAG or data-migration changes: no re-login, no vault re-unlock. Vaults stuck
  on this failure recover on the first sync after installing this build.
- Android: same signing key, installing over the previous version works normally.
- macOS: manual installation from the DMG is still required (self-signed build).
- Evidence: regression tests proved red before the change and green after it (lost image reference,
  already queued batch, purged image), `flutter analyze` clean, 31 tests passed across the new and the
  sync/image suites, full preflight green before release.

## Polski

- Naprawione: synchronizacja mogła zawisnąć na stałe na vaulcie, którego historia cytuje obrazek
  nieistniejący już lokalnie (np. obrazek usunięty z notatki albo wyczyszczony po tym, jak zdążył
  trafić na poprzedni serwer). Przy ponownym wysłaniu vaulta na inny serwer każdy batch z takim
  odwołaniem był odrzucany kodem `409 Image not uploaded yet`, więc cała historia stała w miejscu —
  a lokalnie nie było już bajtów, którymi można by spełnić wymóg serwera.
- Upload podaje teraz wyłącznie odwołania do obrazków, których bajty są jeszcze dostępne lokalnie,
  i tak samo filtruje batch już zakolejkowany, nadając mu nowy identyfikator. Treść notatek i payload
  rewizji nie są zmieniane: redukowana jest tylko lista odwołań do obrazków po stronie serwera.
  Dotknięta historyczna wersja może na innym urządzeniu pokazać zaślepkę w miejscu tego jednego
  obrazka; notatki i reszta historii pozostają bez zmian.
- Obrazek, który serwer zgłasza jako wyczyszczony (`purged`), nie jest już oznaczany jako wysłany,
  więc nie może w cichy sposób blokować batcha; ponowienie idzie dalej z pozostałymi odwołaniami.
- Brak zmian protokołu, szyfrowania, DAG i migracji danych: żadnego ponownego logowania ani
  odblokowywania vaulta. Zawieszone vaulty naprawiają się przy pierwszej synchronizacji po instalacji.
- Android: ten sam klucz podpisu, instalacja nad poprzednią wersją działa normalnie.
- macOS: nadal wymagana ręczna instalacja z DMG (build self-signed).
- Dowody: testy regresyjne były czerwone przed zmianą i zielone po niej (utracone odwołanie do
  obrazka, batch już zakolejkowany, obrazek `purged`), `flutter analyze` czysty, 31 testów przeszło
  w nowym zestawie oraz w zestawach sync/obrazy, pełny preflight zielony przed wydaniem.
