# Silique 0.2.53

## English

- Fixed: **synchronization can no longer fail silently.** A vault that the sync pass
  cannot handle — the account recorded for it does not match the signed-in account,
  sync is switched off for it, its key is locked, or a deletion is pending — is now
  reported with its reason in Settings instead of the pass quietly ending as a no-op.
- Fixed: **a vault is identified by its own ID, not by the server it was last synced
  with.** The recorded owner is provenance only ("last synced with this account") and no
  longer acts as an access gate, so pointing the app at a different server does not take
  your own notes away: the vault is re-bound to the signed-in account automatically (its
  key is re-wrapped with the account key and the server copy is created or updated
  against the server's live version). The sync switch stays usable in that state instead
  of turning grey and dead.
- Fixed: **moving a vault to a server that does not know it yet** now re-uploads the
  whole local revision chain, parent before child, in server-sized batches and
  idempotently (`409 Parent revision missing` triggers a full ordered re-upload instead
  of a permanent error, `Revision ID collision` is treated as "already sent").
- Safety: a vault **deleted on the server** is never recreated silently. It is reported,
  local notes and keys are left untouched, and bringing it back requires an explicit
  action from you — a device that sat in a drawer for weeks must not resurrect data you
  deleted on purpose.
- Historical owner values of the form `https://server|account` are read as the account
  they carry; the server part is ignored when deciding what may sync.
- No crypto, AAD or data-migration changes: existing vaults, notes and images open as
  before, and no re-login or vault re-unlock is needed.
- Evidence: `flutter analyze` clean; the new and updated sync tests pass (13 tests across
  five files); the full client suite and the release preflight run green on the release
  commit. Not yet exercised on a physical device — the owner confirms that after
  installing, so treat on-device behaviour as unverified rather than tested.
- Android: same signing key, installing over the previous version works normally.
- macOS: manual installation from the DMG is still required (self-signed build).

## Polski

- Naprawione: **synchronizacja nie może już kończyć się ciszą.** Vault, którego przebieg
  synchronizacji nie może obsłużyć — zapisane konto nie zgadza się z zalogowanym, sync
  jest dla niego wyłączony, klucz jest zablokowany albo czeka usunięcie — jest teraz
  raportowany z powodem w Ustawieniach, zamiast kończyć przebieg jako ciche „nic się nie
  stało".
- Naprawione: **vault jest identyfikowany własnym ID, a nie serwerem, z którym był
  ostatnio synchronizowany.** Zapisany właściciel jest wyłącznie pochodzeniem („ostatnio
  zsynchronizowany z tym kontem") i nie działa już jak brama dostępu, więc wskazanie
  innego serwera nie odbiera dostępu do własnych notatek: vault jest automatycznie
  przepinany na zalogowane konto (klucz jest opakowywany kluczem konta, a kopia na
  serwerze tworzona lub aktualizowana względem wersji z serwera). Przełącznik
  synchronizacji pozostaje wtedy używalny, zamiast być szary i martwy.
- Naprawione: **przeniesienie vaulta na serwer, który go nie zna**, wysyła teraz cały
  lokalny łańcuch rewizji — rodzic przed dzieckiem, w partiach mieszczących się w limicie
  serwera i idempotentnie (`409 Parent revision missing` wywołuje pełny ponowny upload w
  kolejności, zamiast trwałego błędu; `Revision ID collision` jest traktowane jako „już
  wysłane").
- Bezpieczeństwo: vault **usunięty na serwerze** nigdy nie jest odtwarzany po cichu. Jest
  raportowany, lokalne notatki i klucze zostają nietknięte, a przywrócenie wymaga Twojej
  jawnej akcji — urządzenie, które leżało tygodniami w szufladzie, nie może wskrzesić
  danych usuniętych świadomie.
- Historyczne wartości właściciela w formacie `https://serwer|konto` są czytane jako
  konto, które niosą; część serwerowa jest ignorowana przy decyzji o synchronizacji.
- Bez zmian w kryptografii, AAD i bez migracji danych: istniejące vaulty, notatki i obrazy
  otwierają się jak dotąd, bez ponownego logowania i bez odblokowywania vaulta.
- Dowody: `flutter analyze` czysto; nowe i zaktualizowane testy synchronizacji przechodzą
  (13 testów w pięciu plikach); pełny zestaw klienta i preflight wydania są zielone na
  commicie wydania. **Nie sprawdzone na fizycznym urządzeniu** — potwierdza właściciel po
  instalacji, więc zachowanie na urządzeniu traktuj jako niezweryfikowane, nie jako
  przetestowane.
- Android: ten sam klucz podpisu, instalacja na poprzednią wersję działa normalnie.
- macOS: nadal wymagana ręczna instalacja z DMG (build self-signed).
