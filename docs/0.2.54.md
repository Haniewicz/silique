# Silique 0.2.54

## English

- Fixed: after switching a vault to another server (0.2.53 re-binds a vault to the signed-in
  account instead of blocking it), synchronization could get stuck forever with
  `Image not uploaded yet` in the sync status panel. The new server rejected the whole batch
  with `409 Image not uploaded yet` because the notes cited an image whose manifest that server
  had never received, while the client considered the image already uploaded (it had been sent
  to the previous server) and never re-sent it. Every subsequent pass failed the same way.
- The client now re-marks all images of a vault for upload whenever it re-creates the vault on a
  fresh server (and when it recovers from `Parent revision missing`). A `409 Image not uploaded
  yet` is also self-healed once: images are re-uploaded and the same batch is retried. Repeating
  a chunk or manifest upload is a no-op on the server, so this is safe for images that are
  already there.
- If the images still cannot be completed, the app shows a readable Polish/English message
  (notes remain safe locally and sync is retried) instead of the raw server error. A locally
  missing image chunk is reported with the image and note identifiers instead of crashing.
- No protocol, crypto or data-migration changes: no re-login, no vault re-unlock, no change to
  the revision DAG or the tombstone rules. Existing stuck vaults recover on the next sync after
  installing this build — no manual repair is needed.
- Android: same signing key, installing over the previous version works normally.
- macOS: manual installation from the DMG is still required (self-signed build).
- Evidence: the defect was reproduced against the real server code path (`409` on the batch,
  accepted after the image upload, repeated chunk/manifest PUTs idempotent); regression tests
  proved red before the fix and green after (10/10 server-switch tests, 28 passed / 3 skipped
  across the sync and image suites), `flutter analyze` clean, full preflight green before release.

## Polski

- Naprawione: po przełączeniu vaulta na inny serwer (0.2.53 przypisuje vault do zalogowanego
  konta zamiast go blokować) synchronizacja mogła zawisnąć na stałe z komunikatem
  `Image not uploaded yet` w panelu statusu. Nowy serwer odrzucał cały batch kodem
  `409 Image not uploaded yet`, bo notatki cytowały obrazek, którego manifest nigdy do niego nie
  dotarł — a klient uznawał obrazek za już wysłany (poszedł na poprzedni serwer) i nie wysyłał go
  ponownie. Każdy kolejny przebieg kończył się tak samo.
- Klient oznacza teraz wszystkie obrazki vaulta do ponownego wysłania, gdy odtwarza vault na
  świeżym serwerze (oraz przy odzyskiwaniu z `Parent revision missing`). `409 Image not uploaded
  yet` jest dodatkowo samonaprawiany raz: obrazki lecą ponownie, a ten sam batch jest powtarzany.
  Powtórzenie wysłania chunka lub manifestu jest dla serwera no-opem, więc jest to bezpieczne
  także dla obrazków, które już tam są.
- Jeśli obrazków nadal nie da się uzupełnić, aplikacja pokazuje czytelny komunikat po polsku
  i angielsku (notatki są bezpieczne lokalnie, synchronizacja zostanie ponowiona) zamiast surowego
  błędu serwera. Brak lokalnego fragmentu obrazka jest zgłaszany z identyfikatorem obrazka
  i notatki, zamiast kończyć się crashem.
- Brak zmian protokołu, szyfrowania i migracji danych: żadnego ponownego logowania ani
  odblokowywania vaulta, bez zmian w DAG rewizji i w regułach tombstone. Zawieszone vaulty
  naprawiają się same przy pierwszej synchronizacji po instalacji tej wersji — bez ręcznej naprawy.
- Android: ten sam klucz podpisu, instalacja nad poprzednią wersją działa normalnie.
- macOS: nadal wymagana ręczna instalacja z DMG (build self-signed).
- Dowody: defekt odtworzono na prawdziwej ścieżce serwera (`409` na batchu, batch przyjęty po
  wysłaniu obrazka, powtórne PUT chunka/manifestu idempotentne); testy regresyjne były czerwone
  przed poprawką i zielone po niej (10/10 testów przełączania serwera, 28 przeszło / 3 pominięte
  w zestawach sync i obrazków), `flutter analyze` czysty, pełny preflight zielony przed wydaniem.
