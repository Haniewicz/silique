# Silique 0.2.7 — build 12

Wydanie [Silique 0.2.7](https://github.com/Haniewicz/silique-releases/releases/tag/v0.2.7) opublikowano 2026-10-22 na polecenie właściciela, na podstawie zmian wykonanych na Fedorze. Obejmuje siedem instalatorów i SHA256. Oba podpisane kanały wskazują 0.2.7+12; kod aplikacji i serwera pozostaje prywatny.

## Zmiany

- Naprawiono przewijanie ustawień kółkiem myszy w GTK4. Gdy zdarzenie GDK_SCROLL nie zawiera współrzędnych, silnik odtwarza je z głównego wskaźnika GdkSeat i uwzględnia offset natywnego nagłówka. Odrzuca niefinitywne dane.
- Lista urządzeń pomija pozycje z cofniętym dostępem; po udanym odłączeniu wiersz znika od razu. Audyt serwera pozostaje bez zmian.
- Instalacje Linux zarządzane przez RPM/DEB automatycznie sprawdzają podpisany kanał. Użytkownik wybiera pobranie i instalację, a systemowa autoryzacja pkexec uruchamia DNF/APT. Wcześniej klient weryfikuje podpis manifestu, kanoniczne URL-e, rozmiar i SHA256 oraz zapisuje notatki. Rozpoznaje pakiet, który rzeczywiście posiada uruchomioną binarkę; tar.gz pozostaje ręczny.
- Linux tworzy prywatny katalog pobierania przez mktemp z trybem 0700 od początku. Android zachowuje stały katalog cache zgodny z natywnym instalatorem i FileProvider. Bez zmian tożsamości aplikacji, klucza wydania i istniejących vaultów.
- Runner GTK4 wyłącza opcjonalny most JNI, aby obecność JDK na builderze nie dodawała zależności libjvm do paczek.

Pierwsze przejście z Linux 0.2.6 do 0.2.7 jest ręczne. Windows i portable Linux nadal aktualizuje się przez stronę wydań. macOS/Android zachowują aktualizator z potwierdzaną instalacją.

## Ograniczenia

GTK4 pozostaje eksperymentalnym portem Fluttera. Wymagania Linux: GTK4 >= 4.14, glibc >= 2.39, Secret Service i działający polkit/pkexec do aktualizacji z aplikacji. Instalator dostaje ścieżkę po weryfikacji klienta: katalog 0700 chroni przed innymi użytkownikami, nie przed złośliwym procesem już działającym jako ten sam użytkownik. Root nie wykonuje oddzielnej weryfikacji Ed25519.

RPM nie ma podpisu OpenPGP, EXE nie ma Authenticode, macOS jest podpisany lokalnie bez notaryzacji Apple. APK używa dotychczasowego certyfikatu. Nie zmieniono reguł zaufania systemu ani magazynów kluczy; prywatne logi i źródła pozostają poza publicznym wydaniem.

Po publikacji zweryfikowano rozmiary i SHA256 wszystkich ośmiu zasobów GitHub. Oba kanały i plik sum pobrano bez uwierzytelnienia i porównano z przygotowanym wydaniem; klucz wbudowany w klienta potwierdził podpis publicznego manifestu 0.2.7+12.

Końcowy test rzeczywistego klienta updatera pobrał pełny publiczny APK bez konta GitHub i zaliczył weryfikację podpisu manifestu, rozmiaru i SHA256. Publiczny manifest ma wersję 0.2.7, build 12 i siedem paczek.
