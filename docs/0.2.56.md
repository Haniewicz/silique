# Silique 0.2.56

## English

- A stalled vault is no longer silent. Each vault now records when it last synced successfully, when
  it last tried, the last error and its time, plus how many revisions are still waiting and how many
  notes are divergent (more than one head). The new "Sync status" dialog shows those numbers for the
  selected vault, and the sync indicator opens it directly while that vault is failing.
- A failing vault no longer stops the others. Previously one exception escaped the whole pass, so a
  single broken vault prevented every other vault from pulling; each vault now records its own
  failure, the remaining vaults still sync, and the pass reports the first error afterwards.
- New action "Force full pull": replays the vault's whole changelog from the beginning and then
  materialises it (merge, conflicts, image cache) without writing anything to the server. This is the
  only recovery path for a vault whose uploads keep failing, because a regular pass never reaches its
  download phase.
- New action "Send pending changes": drains the queued batch and the pending revisions with bounded
  uploads and reports what is left.
- New action "Set this device as the source of truth…", behind a second confirmation that lists the
  counts, states the consequences and lets you keep losing versions as copies. It pulls the full
  history first, then writes one new version per note whose parents are all existing server versions
  (chained above the server's 32-parent limit), writes deletions for notes deleted here and for
  remote versions with no local content, and retires only the queued revisions it actually
  supersedes. Version history stays in the vault database; a successful reset ends with zero
  divergent notes. Hidden notes are outside its scope and are reported as such.
- Fixed: synchronization could stay blocked by a note that cites an image the server no longer has.
  The image lookup happens between the download and the upload phase, and every failure escaped, so
  one lost attachment aborted each pass before that device's own edits were sent. A `404` now leaves
  the image remote-only (the editor keeps its placeholder); every other image failure is still
  reported.
- No protocol, crypto, DAG or data-migration changes, and no server change: the server remains a dumb
  immutable store. Existing vaults keep working; the new status starts empty and fills in with the
  first sync after installing this build.
- Android: same signing key, installing over the previous version works normally.
- macOS: manual installation from the DMG is still required (self-signed build).
- Evidence: `flutter analyze` clean, full suite green, 23 new tests in `test/sync_recovery_test.dart`
  covering status recording, per-vault failure isolation, full pull from a stale cursor, queue drain,
  parent chains at the 32/33 head boundary, queue retirement restricted to superseded revisions,
  hidden-note exclusion, deterministic idempotent copies and the destructive confirmation flow. Three
  regression tests were proven red before their fix: the 410 tombstone path, a note that exists only
  locally at reset time, and the lost-image `404` pass abort. Two independent review rounds returned
  blocking findings that were fixed and re-reviewed. Design and non-goals: `docs/sync-recovery.md`.

## Polski

- Zatrzymany vault nie jest już niemy. Każdy vault zapisuje teraz czas ostatniej udanej
  synchronizacji, czas ostatniej próby, ostatni błąd i jego czas, liczbę oczekujących rewizji oraz
  liczbę notatek rozbieżnych (więcej niż jedna głowa). Nowy dialog „Status synchronizacji" pokazuje te
  liczby dla wybranego vaulta, a wskaźnik synchronizacji otwiera go wprost, gdy dany vault ma błąd.
- Awaria jednego vaulta nie zatrzymuje pozostałych. Wcześniej pojedynczy wyjątek uciekał z całego
  przebiegu, więc jeden zepsuty vault blokował pobieranie wszystkim innym; teraz każdy vault zapisuje
  własną porażkę, pozostałe synchronizują się normalnie, a przebieg zgłasza pierwszy błąd na końcu.
- Nowa akcja „Wymuś pełne ściągnięcie": odtwarza cały changelog vaulta od początku, a następnie
  materializuje go (scalanie, konflikty, cache obrazów) bez zapisywania czegokolwiek na serwerze. To
  jedyna droga ratunku dla vaulta, którego wysyłka stale pada, bo zwykły przebieg nigdy nie dochodzi
  wtedy do fazy pobierania.
- Nowa akcja „Wyślij oczekujące zmiany": opróżnia zakolejkowany batch i oczekujące rewizje ograniczoną
  liczbą wysyłek i raportuje, co zostało.
- Nowa akcja „Ustaw to urządzenie jako źródło prawdy…", za drugim potwierdzeniem, które podaje liczby,
  opisuje skutki i pozwala zachować przegrywające wersje jako kopie. Najpierw pobiera pełną historię,
  potem zapisuje po jednej nowej wersji każdej notatki, której rodzicami są wszystkie istniejące wersje
  na serwerze (łańcuch powyżej limitu 32 rodziców), zapisuje kasowania dla notatek usuniętych tutaj
  i dla zdalnych wersji bez lokalnej treści, a z kolejki wycofuje tylko te rewizje, które faktycznie
  zastępuje. Historia wersji pozostaje w bazie vaulta; udany reset kończy się zerem notatek
  rozbieżnych. Ukryte notatki są poza jego zakresem i są tak zgłaszane.
- Naprawione: synchronizacja mogła stać przez notatkę cytującą obrazek, którego serwer już nie ma.
  Sprawdzenie obrazka wypada między pobieraniem a wysyłką, a każdy błąd uciekał — jeden utracony
  załącznik przerywał więc każdy przebieg, zanim własne zmiany tego urządzenia zostały wysłane. Kod
  `404` zostawia teraz obrazek wyłącznie po stronie serwera (edytor pokazuje zaślepkę); pozostałe
  błędy obrazków nadal są zgłaszane.
- Brak zmian protokołu, szyfrowania, DAG i migracji danych oraz brak zmian po stronie serwera — serwer
  pozostaje niemym, niezmiennym magazynem. Istniejące vaulty działają dalej; nowy status startuje
  pusty i wypełnia się przy pierwszej synchronizacji po instalacji.
- Android: ten sam klucz podpisu, instalacja nad poprzednią wersją działa normalnie.
- macOS: nadal wymagana ręczna instalacja z DMG (build self-signed).
- Dowody: `flutter analyze` czysty, pełny zestaw zielony, 23 nowe testy w `test/sync_recovery_test.dart`
  obejmujące zapis statusu, izolację awarii per vault, pełne pobranie przy nieaktualnym kursorze,
  opróżnianie kolejki, łańcuch rodziców na granicy 32/33 głów, wycofywanie z kolejki tylko rewizji
  zastąpionych, wyłączenie ukrytych notatek, deterministyczne i idempotentne kopie oraz przepływ
  potwierdzenia akcji niszczącej. Trzy testy regresyjne były czerwone przed poprawką: ścieżka
  tombstone'a 410, notatka istniejąca tylko lokalnie w chwili resetu oraz utracony obrazek `404`
  przerywający przebieg. Dwa niezależne roundy review zwróciły blokujące uwagi, które naprawiono
  i sprawdzono ponownie. Projekt i nie-cele: `docs/sync-recovery.md`.
