# Silique 0.2.34+43 — desktop UX candidate

Status: **opublikowane 2026-10-29** jako [v0.2.34](https://github.com/Haniewicz/silique-releases/releases/tag/v0.2.34) na jawne polecenie właściciela „Opublikuj”. Nie odbył się osobisty test właściciela ani instalacja na jego urządzeniach; zgoda dotyczyła tej publikacji i nie jest stałym upoważnieniem.

## Changes

1. Desktop link labels use native text glyphs so individual characters, reverse selections and wrapped labels can be selected/copied; link opening remains a separate unmoved pointer action. Touch projection is preserved.
2. Desktop text menus expose Undo, Redo, Cut, Copy, Paste, Delete and Select All with state-aware availability. Source/live/embedded editors share document history; stale hidden-editor callbacks cannot restore plaintext after lock.
3. Folder top/bottom edge drops reorder siblings; centre drops still nest. Preferences are encrypted vault metadata, persist across SQLite reopen and merge independently from membership. Stale in-flight metadata responses cannot undo newer confirmed orders. Locked/offline merging preserves remote names and unknown metadata fields.
4. Close requests share a single save/close attempt. Normal close uses a nonwaiting PASSIVE checkpoint; updater handoff retains strict checked TRUNCATE, write fencing and draining. No forced exit, production timeout, early hide or omitted save. The external Windows probe measures natural process exit and fresh-process durability on baseline/final; its result is not yet recorded here.
5. Alt/AltGraph events do not activate Ctrl/Meta commands. Modeled tests cover lowercase/uppercase Polish letters in title/live/source and preserve ordinary shortcuts. OS keyboard layout remains authoritative; left Alt is not made into a character synthesizer.
6. One import action offers a Markdown/TXT document or a whole folder. Both use preview, destination and explicit confirmation; folder imports retain images, hierarchy and rewritten internal links. A single selected file preserves literal text/references and never enumerates neighbours. Source files are not modified.
7. Deleted, Hidden and Import form a horizontal footer above vault badge/count/settings, including the phone drawer. PL/EN and enlarged-text navigation are covered. Import remains disabled in hidden/locked contexts.
8. Keychain bundle reuse is bounded to the existing cross-process credential gate. Existing startup no longer enumerates unrelated preserved legacy items; each new acquisition reloads, admitted operations drain, errors propagate. No key/namespace/signature change or local fallback.
9. Former presentation branding is removed where safe. Exact storage, crypto, install, discovery and signing identifiers and historical provenance are retained under the tested contract in [rebrand.md](rebrand.md).

## Portable evidence

- Local complete Flutter suite: 921 passed, 45 skipped, no failures (`full-local.log`, private state). Skips include native-only/disposable-server tests; they are not counted as passes.
- Subsequent affected suites verify the explicit native clipboard seam and same-open-scope error invalidation. Counts are separate, not added to the complete suite.
- Real disposable two-client HTTP/SQLite regressions reproduce and verify stale GET and locked-merge metadata preservation, convergence and no settled write loop.
- Branding contract checks exact assignments/certificate fingerprint and rejects arbitrary former-brand use outside narrow paths. Actual encrypted-data migration/reopen tests retain keys, identity and pending revisions.
- Native runner results and exact build/preparation provenance belong in the final private delivery report; none is implied by these portable tests.

## Boundaries

Windows shared-reader tests do not prove the owner's 3–4 second process-exit cause: production normally uses exclusive SQLite. Native timing controls, real save refusal/retry and process-reopen assertions are separate evidence. Physical Polish-layout composition and interactive post-update Keychain authorization still require the owner's environment; CI cannot establish its existing item ACL/trust history.

The existing Android file-selector may pre-copy the selected file before returning an XFile. The 1 MB application/import limit is enforced, but is not a claim of end-to-end bounded picker allocation. This inherited picker behavior is unchanged by the desktop UX work.

macOS keeps the existing preview signing identity, not Developer ID notarization. Windows remains without Authenticode. Valid updater/package signatures do not prove Gatekeeper, interactive UAC or owner installation/relaunch acceptance. No production server, owner data or installation was changed.
