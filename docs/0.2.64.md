# Silique 0.2.64

## English

- The Android launcher list and the native widget search no longer present a
  read failure as an empty vault. A locked screen shows the locked header, and
  an index that cannot be read right now (Keystore not usable yet, a transient
  I/O problem) shows a short "temporarily unavailable" hint instead of "No
  notes". A genuinely empty vault still shows the ordinary empty hint.
- The last good encrypted widget snapshot is no longer deleted by a rejected
  publish, a transient read failure or a vault-deletion cleanup that cannot
  read it. Only a real decryption/format failure (or an impossible frame size)
  drops it, and the deletion cleanup then reports the pending cleanup instead
  of pretending the index was empty.
- A render that lands locked or unreadable now arms the existing bounded retry
  (60 s, up to 30 ticks), so the widget repaints by itself once the screen is
  unlocked or the index becomes readable again. The app also republishes the
  snapshot whenever it returns to the foreground.
- A failed widget publish is retried on the next refresh even when the note
  data did not change. Previously the stale in-memory "already published"
  marker silently skipped the retry, which is why opening the app did not
  always bring the notes back.
- New diagnostics for the owner: Settings → General → Widget diagnostics shows
  and copies a bounded (64 KiB) log of widget reads, renders and retry polls —
  timestamps, counts and exception class names only. It never records note
  titles, bodies, folders or search queries.
- The native widget search shows a status line (locked / temporarily
  unavailable) instead of an empty result list when it cannot read the index.
- No protocol, crypto, snapshot-format, database-migration, dependency or
  server changes. The same Android signing key is used, so installing over the
  previous version works normally; macOS still requires manual installation
  from the DMG (self-signed build).

## Polski

- Lista notatek w widżecie Androida i natywna wyszukiwarka widżetu nie
  pokazują już błędu odczytu jako pustego vaulta. Zablokowany ekran pokazuje
  nagłówek o blokadzie, a indeks, którego nie da się teraz odczytać (klucz
  Keystore jeszcze niedostępny, chwilowy problem I/O), pokazuje krótką
  informację „notatki chwilowo niedostępne” zamiast „Brak notatek”. Faktycznie
  pusty vault nadal pokazuje zwykły pusty stan.
- Ostatni dobry zaszyfrowany snapshot widżetu nie jest już kasowany przez
  odrzuconą publikację, chwilowy błąd odczytu ani sprzątanie po usunięciu
  vaulta, które nie potrafi go odczytać. Kasuje go tylko prawdziwe uszkodzenie
  odszyfrowania/formatu (lub niemożliwy rozmiar ramki); sprzątanie po usunięciu
  zgłasza wtedy oczekujące sprzątnięcie, zamiast udawać pusty indeks.
- Render, który wypadł na zablokowanym ekranie albo przy nieczytelnym indeksie,
  uzbraja dotychczasowy ograniczony retry (60 s, do 30 ticków), więc widżet sam
  się odświeży po odblokowaniu ekranu albo odzyskaniu czytelności indeksu.
  Aplikacja publikuje snapshot ponownie także po powrocie na wierzch.
- Nieudana publikacja snapshotu jest ponawiana przy następnym odświeżeniu nawet
  gdy dane notatek się nie zmieniły. Wcześniej nieaktualny znacznik „już
  opublikowano” w pamięci po cichu pomijał ponowienie — dlatego otwarcie
  aplikacji nie zawsze przywracało notatki w widżecie.
- Nowa diagnostyka dla właściciela: Ustawienia → Ogólne → Diagnostyka widżetów
  pokazuje i kopiuje ograniczony (64 KiB) dziennik odczytów, renderów i prób
  ponowienia — tylko znaczniki czasu, liczniki i nazwy klas wyjątków. Nigdy nie
  zapisuje tytułów, treści, folderów ani zapytań wyszukiwania.
- Natywna wyszukiwarka widżetu pokazuje linię statusu (zablokowane / chwilowo
  niedostępne) zamiast pustej listy wyników, gdy nie może odczytać indeksu.
- Bez zmian protokołu, kryptografii, formatu snapshotu, bazy, zależności i
  serwera. Ten sam klucz podpisu Androida, więc instalacja na poprzednią wersję
  działa normalnie; macOS nadal wymaga ręcznej instalacji z DMG (build
  self-signed).
