# Silique 0.2.8 — build 17

Wydanie [Silique 0.2.8](https://github.com/Haniewicz/silique-releases/releases/tag/v0.2.8) opublikowano 2026-10-22 na polecenie właściciela. Obejmuje macOS ZIP, Android APK, Windows EXE/ZIP i Linux GTK4 DEB/RPM/tar.gz oraz SHA256. Oba podpisane kanały wskazują 0.2.8+17. Źródła pozostają prywatne.

## Zmiany

- Import Obsidiana obsługuje Unicode, emoji, dosłowny procent i zakodowane ścieżki. Osadzone CSV, PDF, Bases, MHT i inne pomijane formaty nie blokują importu; oryginalne odnośniki pozostają w treści bez kopiowania załączników. Podgląd to wyjaśnia.
- Checkboxy automatycznie otrzymują spację po domknięciu znacznika. Enter zachowuje puste zadanie i tworzy następne. Poprawiono podgląd pustych znaczników oraz klikanie checkboxów.
- Breadcrumbs vaulta i folderów pozwalają przejść do wybranego miejsca. Zaznaczanie wszystkich obejmuje widoczne wyniki filtra.
- Na telefonie gest otwiera nawigację; poprawiono wyszukiwanie przy klawiaturze, widoczność kursora, emoji oraz menu.
- Synchronizacja reaguje na zapis i zdalne zmiany; nowszy serwer obsługuje long poll, a starsze serwery zachowują zgodność. Usunięto zbędny napis „Zapisywanie…”.

## Źródła i weryfikacja

Wszystkie paczki pochodzą z kodu `b94ed610be714cc4d9a2420f173cbff67bb493d8`; późniejszy commit zamyka wyłącznie dokumentację wydania. Zachowano identyfikatory instalacji, format szyfrowania i klucze wydania.

- macOS: 163 testy z osobnym API zaliczone, 6 jawnie pominiętych (5 zależnych od Linuxa i publiczny smoke). Analizator bez uwag. Uniwersalny ZIP arm64/x86_64, lokalny podpis i zgodność binariów ZIP z jedyną instalacją `/Applications/Silique.app` 0.2.8+17 zweryfikowane.
- Import: 14 testów importu i okna, w tym wąski ekran, odtworzenie obu błędów na starym kodzie, zachowanie źródeł i osadzonych odnośników, deduplikacja obrazów oraz ponowny odczyt po zamknięciu bazy. Dotychczasowe kontrole granic folderu i wycofywania nieudanego importu pozostają aktywne.
- Android: produkcyjny APK 0.2.8+17, poprawny podpis v2 z dotychczasowym certyfikatem oraz zgodność identyfikatora i wersji. Nie powtarzano natywnego testu emulatora dla końcowego build 17; wcześniejszy test mobilny build 13 jest opisany w historii przygotowania.
- Windows: [Actions 39791249480](https://github.com/Haniewicz/silique-releases/actions/runs/39791249480) zakończone sukcesem. Natywny test magazynu kluczy, SQLite, edytora, importu i wersji aplikacji; instalacja EXE, zgodność plików, otwarcie produkcyjnego okna i deinstalacja zaliczone. Rozmiary/SHA256 EXE i ZIP zgodne z raportem; ZIP bez źródeł, PDB i materiałów podpisu.
- Linux: użyto zachowanego cache w CT 104. SDK odpowiada dokładnie łatce wydania `c1e6e3b8dafd1996f63b286563f50080b0c779a407a5d4033ca4d18767942d32`. 158 testów zaliczonych, 11 pominiętych (API/publiczny smoke), analizator czysty. Probe AOT zaliczył 14 kontroli, w tym import i odczyt chronionego vaulta. Rzeczywiste kółko w produkcyjnych ustawieniach: PASS, 56 312 zmienionych pikseli. Zaktualizowano testowe DEB/RPM z 0.2.6 do 0.2.8+17; instalacja i uruchomienie na Ubuntu 24.04/Fedora 44 zaliczone. CT 104 ponownie wyłączony, cache zachowany. Pełną kompilację Actions 39791256314 anulowano po przejściu na zachowany cache; nie jest źródłem paczek.
- Publikator: 4 testy granic publikacji zaliczone. Po przerwanym równoległym przesyłaniu uzupełniono szkic pojedynczymi plikami i ponowiono publikator. Przed publikacją sprawdził komplet ośmiu zasobów i ich SHA256; następnie zaktualizował oba podpisane kanały.
- Po publikacji ponownie zweryfikowano osiem zasobów GitHub, pobrano oba kanały bez uwierzytelnienia i potwierdzono ich identyczność z przygotowanym wydaniem. Klucz wbudowany w klienta zweryfikował manifest 0.2.8+17. Rzeczywisty klient aktualizatora zaliczył publiczne pobranie APK oraz kontrolę rozmiaru i SHA256 bez konta GitHub.

Raporty i paczki: `Wydania/0.2.8-kandydat/` obok repozytorium aplikacji; finalne pliki w `podpisane-wydanie/`. Nie publikowano prywatnych logów ani źródeł.

## Ograniczenia

GTK4 pozostaje eksperymentalne; nie powtarzano natywnego testu Wayland ani pełnego restartu Sparkle na danych właściciela. macOS ma podpis lokalny bez notaryzacji, EXE nie ma Authenticode, RPM nie ma OpenPGP. Dotychczasowy podpis Ed25519 wiąże adresy, rozmiary i SHA256 paczek. Windows i portable Linux aktualizuje się ręcznie; macOS, Android oraz RPM/DEB oferują aktualizację z aplikacji z potwierdzeniem. Serwera nie zmieniano w ramach publikacji; przygotowane wcześniej 0.2.3 pozostaje wdrożone.
